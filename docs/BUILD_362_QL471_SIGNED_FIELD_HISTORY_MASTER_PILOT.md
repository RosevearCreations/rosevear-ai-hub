## Independent field package format

The user or approved custodian provides a real field package, outside the repository and outside web uploads:

- receipt.json: exact schema rosevear.hub.ql471.field-claim362.v1, fields schema, scope, host, sourceCommit, drillId, eventId, nonce, observedAt, issuedAt, evidenceSha256, signerKeyFingerprint, checks
- signature.b64: detached base64 Ed25519 signature over UTF-8 canonical sorted compact JSON receipt
- evidence.bin: nonempty *sanitized* evidence bytes, SHA-256 committed in receipt. Do not include passwords, access tokens, camera frames, customer data or private keys
- signer.pub.pem: signer Ed25519 public key only

The five scopes are reboot-before, reboot-after, guest, ai-data-worker, comms-worker. Exact required checklist names are specified in CHECKS in server/src/rosevear_ai_hub/signed_intake362.py. Every check must be true. A signed checklist authenticates the signer assertion; it does not establish that the test actually took place.

An independent owner channel must provide a private trusted-pins.json with exactly those five scope names mapped to **five different SHA-256 fingerprints of the raw Ed25519 public keys** (64 lowercase hexadecimal characters). A pin copied directly from the package does not provide independent trust. The signer private keys are never loaded or generated by the Hub. No physical actions are performed by this intake.

The receipt must name original host DESKTOP-AE894KC and the exact original-PC installed 40-character git source commit. Times are UTC with terminal Z; field claims expire after 24 hours and cannot be signed more than two hours after the observation. Event IDs and signing nonces must not be reused. A **new history ledger** is required when the original PC changes installed source commit.

## Operator workflow (opt-in, local, NO service activation)

Run from the original Hub checkout using its existing Python environment after the source release is adopted locally. Verify the checkout has the dependencies installed, for example with the standard backend editable install when appropriate. Do not touch an unrelated untracked package-lock.json.

Dry-run signature verification, with no file write:

    python scripts/intake-signed-field-evidence362.py --package-dir "C:\PRIVATE\ql471\sample-01" --trusted-pins-json "C:\PRIVATE\ql471\trusted-pins.json" --expected-commit ACTUAL_40_HEX_SOURCE_COMMIT

If an authorized custodian approves a private history update, use a ledger path that already has a private existing parent directory **outside the repository**:

    python scripts/intake-signed-field-evidence362.py --package-dir "C:\PRIVATE\ql471\sample-01" --trusted-pins-json "C:\PRIVATE\ql471\trusted-pins.json" --expected-commit ACTUAL_40_HEX_SOURCE_COMMIT --ledger "C:\PRIVATE\ql471\signed-history.json" --append

The script validates source/host/schema, strict evidence digest, trusted distinct scope keys, detached signatures, freshness and all claims. It rejects duplicate event IDs and signer/nonces. It limits the history to 48 entries and writes a summary-only JSON file by atomic replace with an exclusive lock. Do not assume Windows file ACLs are set correctly: place that parent directory under suitable private owner permissions. Raw packages and private keys are not written to the summary file. The local ledger hash chain is **not** independent tamper-proof storage; separately anchor its displayed head digest if long-term evidentiary custody is required.

Original-PC server owner-only dashboard input:

- ROSEVEAR_QL471_EXPECTED_COMMIT = current original-PC source SHA (40 lower hex)
- ROSEVEAR_QL471_LEDGER_PATH = private path to that summary JSON

Both are server environment variables; no user can choose the server file path in the browser. The owner-only GET /api/v1/system/server-shell-362 refuses untrusted/nonmatching history and sends no-store headers. The screen reports drill IDs and whether BEFORE/AFTER signed **claims** have a plausible chronological pairing; it never re-verifies Ed25519 signatures at GET time and never turns a paired claim into physical recovery success. No browser import, upload or file-control endpoint exists.
