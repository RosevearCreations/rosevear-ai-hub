# Rosevear AI Hub — Owner-approved 20-build programme (368–387)

**Created:** 2026-11-19. **Starting gate:** Build 367 private TLS signed source receipts. **Exactly 20 proposed builds remain**; none is treated as implemented or authorized network action merely by being queued.

## Product boundaries and target
The purpose is a **single useful home/workshop AI and operations centre**, not 20 more read-only ceremony panels. Home Assistant remains the actual smart-home system of record; independent Master applications remain separate data authorities. Each build must deliver an operator-visible real capability, measurable acceptance and field follow-up. Source/CI GREEN is NOT live home-device field acceptance.

**New scope confirmed by owner:** incomplete household discovery; the Creality printer labelled "Creality Pro 5" (exact model/firmware must be verified before adapter development); Alexa, Samsung SmartThings, Apple Home/Matter and other vendors; network sequencing/process health; grocery ordering board; robust security; screen formatting, field width, date pickers, sixteen Master themes and device ergonomics.

**Build economics:** Each build aims for **5–10 percentage points improvement within its explicitly named module(s)** when source code and testing justify it. This is a target, not an automatic +5/10 points to overall readiness. Overall completion is recalculated whenever the 24-module denominator changes, with signed field acceptance scored separately. An under-delivered build must remain open and consolidate work, not claim progress.

**Safety:** Tier 0 read-only network/home observations may run under approved scope; Tier 1 low-risk actions require explicit owner scopes; Tier 2 purchases, external messages, deletes, network changes and remote restarts require exact-action confirmation; **Tier 3: no autonomous forge, kiln, CNC, laser, printer motor/heat, access locks, security disarm or life-safety devices**. Discovery must be opt-in and network bounded. Physical printer/health data are not assumed from generic API compatibility.

- **368–371:** Trust/identity before network discovery, whole-home inventory, printer and radio protocol bridges. Do not scan all devices to "find everything" without a bounded owner consent scope.
- **372–375:** Alexa/Apple/Samsung/camera interoperability only through provider-supported protocols; each can remain unsupported when real account/device acceptance is absent.
- **376–380:** Household and workshop workflows, grocery board and AI. Sensitive/dangerous actions remain supervised or prohibited.
- **381–384:** Original-host continuity, security and actual Master and seven-app signed acceptance; private receiver QL-340C is not implicitly authorized.
- **385–387:** IT operations, cosmetic parity, real client testing and production runbooks. A final percentage is contingent on real field proof.

**Release per build:** feature branch/PR into `dev` when required, isolated protected-`main` PR for only approved changes (do not merge divergent branch histories), protected six-check CI, exact protected-`main` push verification, original Windows supervised installation and field evidence. Preserve protected `dev` and `main`; remove only merged temporary branches when independently checked.
