# Rosevear AI Hub 296 — Independent Windows Custody Review Exception Register, Owner-Approved Field Receipt Checklist & Read-Only Shell Evidence Readiness Alignment

## Delivered scope
Build 296 extends System → Original Windows adoption → Build 295 custody with three explicit browser-only, non-authorizing owner-review features.

1. **Independent custody exception register (HOLD).** Derives four possible exception types from current locally reported metadata: missing custody note, stale note (over 30 minutes), missing blocked handoff dry-run, and immutable missing independent original evidence. The operator can acknowledge and record an OPEN exception note, but cannot close an exception or mark any authority verified. Invalid SHA/time, unobserved issue or missing acknowledgement fails closed. At most 20 notes are kept in-memory.
2. **Owner-approved field receipt checklist (review permission ONLY).** A current source-matched Build 295 custody note is required before the owner may acknowledge seven separate required original-Windows evidence authorities. Recording a checklist means only approval to review later field evidence; it does not sign owner consent, accept the installed host, approve issuer/witness, cryptographically verify a receipt, enroll a source or connect a Shell. Each of seven requirements remains INDEPENDENT_PROOF_NOT_RECEIVED, verified count 0. Up to ten checklist notes are held in the browser.
3. **Read-only Master Shell evidence readiness projection.** Derives only local metadata presence, checklist review and blocked handoff dry-run status. Explicitly marks AI Data Platform and Comms Hub lanes as READ_ONLY_DESIGN_PREVIEW_NOT_PUBLISHED, evidence registry NOT_CONNECTED, receipt acceptance 0, sent messages 0 and authorization false. Even a full local checklist is REVIEW_CHECKLIST_PREPARED_HOLD, never production readiness.

## Owner walkthrough
1. On the original Windows machine, use the earlier Build 293 unsigned evidence review, Build 294 supervised review, and Build 295 owner chain-of-custody note. These are local notes and not original-host identity proof.
2. Under Build 296 — Owner custody exception register, select one actually detected exception, acknowledge that it remains OPEN/HOLD and record a local note. No exception can be resolved by this screen.
3. Under Owner-approved field receipt checklist, inspect the seven required independent authorities and explicitly approve the checklist for future field review only. This is not signed owner consent.
4. Read the Master Shell evidence readiness alignment. The displayed results come only from this browser session. No registry, Windows service, AI Data Platform or Comms Hub was queried. No message was published.
5. Optionally download private metadata-only JSON for the owner's own custody process. Clear Build 295 local review also resets Build 296 local state, and source/snapshot remounts clear session notes.
