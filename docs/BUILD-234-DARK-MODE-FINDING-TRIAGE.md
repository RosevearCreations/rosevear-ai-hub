# Build 234 — Windows Dark Mode Finding Triage & Conditional Repair Authorization Review

**Authorization:** Source-level owner review worksheet only. It does **not** grant or execute a Windows repair, change a device or camera, alter roles, restore backups, activate a relay or independently close a field issue.

## Owner steps on the installed Windows Hub

1. Sign in as the authorized owner/administrator. Select **Dark Mode** using **Display theme** in the sidebar.
2. Open **System → Windows field acceptance & regression matrix**. Record the *actual installed Windows version* and physical owner witness under Build 228; use no GitHub-only or simulator observations.
3. Scroll through Build 232, then select **Open Build 233 owner acceptance & exception review**. On the installed Windows machine, record a genuine, source-supported Dark Mode visual **finding** or **blocked** check with its safe evidence reference, basis, installed version, owner witness and fresh timestamp.
4. Below that worksheet choose **Open Build 234 finding triage & conditional authorization review**. A candidate appears only for the genuine current Build 233 finding. If there are no findings, the queue is empty and no repair can be proposed.
5. Choose a priority based on actual impact. We may **defer** or **request a retest** with a distinct owner reference, limited owner consent and a fresh time. These decisions leave the case open.
6. To request a **conditional UI repair authorization review**, additionally record a distinct on-Windows reproduction reference, narrowly scoped presentation-only action, impact classification, rollback reference and separately supplied reviewer evidence reference. Attest that an outside reviewer supplied the code (the Hub does not authenticate this claim). Enter a new unique owner decision reference, check the limited **review only** consent, and record a fresh timestamp.
7. Copy the redacted, private Build 234 packet if needed for outside review. It is not uploaded or stored after the browser session. Any change to the original Build 233 observation, version, witness, theme or evidence invalidates the linked proposal.

## Critical limits and safety

- Source CI GREEN cannot establish that the Windows mini-server was updated or that an actual monitor, tablet, device, camera or service passed on-site review.
- No authentic owner Dark Mode defect, independent reviewer identity or independently verified closure was provided during implementation. Production starts at **0 candidate repairs, 0 actual repair grants and 0 executed fixes**; test fixtures are synthetic only.
- Even a fully documented **conditional review packet** is an invitation for a distinct authorization decision, **not** permission to change the installed Windows Hub. Live repair scope requires separate authentic findings, independent evidence and explicit owner authorization.
- No background read/probe, external reviewer contact, MQTT/X10 publish, Home Assistant actuation, private camera access, role change, restore or relay operation is performed by this UI.
- Six-app integration remains **DISCONNECTED / HOLD**; private relay **OFF**; QL-275 **UNDER REVIEW / DEFERRED**; first-party vault **SECURITY HOLD**.
- Enter safe tracking codes only; never paste passwords, full logs, private IPs/URLs, images, private device identities or personal data.
